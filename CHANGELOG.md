# Change Log

All notable changes to `@webtides/element-library` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/) and this project adheres to [Semantic Versioning](https://semver.org/). Per-component changelogs live next to each component (`src/components/<name>/<name>.changelog.md`); this file is the aggregated, package-level view.

## Unreleased

### button

- Changed: in an `el-button-group` the control of a button with a neighbour in front lies on the border of that neighbour by itself: it reads the width from the group (`--_el-group-overlap`, internal and inherited), where the group gave the element a negative margin before. The element of such a button stands beside its neighbour and is narrower than its control by that border. Outside of a group nothing changes. ([#206](https://github.com/webtides/element-library/issues/206))

### button-group

- Fixed: the buttons of a group lie on the border of their neighbour on a page whose stylesheet takes the margin off every element (`* { margin: 0 }`, the reset of Tailwind CSS v4). The group pulled a button over the border of the one in front of it with a negative margin of the button (`::slotted`), and a rule of the page wins over such a rule: two outlined buttons had two lines between them, and the group was wider by a border for every button after the first. The group names the width of the border in a property that inherits now (`--_el-group-overlap`), and the button pulls its control over it. ([#206](https://github.com/webtides/element-library/issues/206))
- Changed: a page that put the overlap back itself, with a negative margin for the buttons of a group, takes that rule out: the buttons would lie on each other by two borders. ([#206](https://github.com/webtides/element-library/issues/206))

### checkbox-group-field

- Added: an option can show something in front of its label: `color` is a colour that is drawn as a dot, `icon` the address of an SVG symbol, as an option of `el-segmented-field` has it. Things a user knows by their colour, tags or calendars, are found by it where they are chosen. Both are decorations, hidden from assistive technology: the label stays the name of the option. They are part of the option, so they work for options as an attribute and as a property, and are in server-rendered markup. The dot keeps its colour where the user forces colours. ([#198](https://github.com/webtides/element-library/issues/198))

### combobox-field

- Added: takes content of the page into its control, an element with `slot="start"` or `slot="end"`, and has the button that empties it (`clearable`, `clear-label`), as `el-input-field`, which it extends. ([#168](https://github.com/webtides/element-library/issues/168))

### date-field

- Added: takes content of the page into its control, an element with `slot="start"` or `slot="end"`, and has the button that empties it (`clearable`, `clear-label`), as `el-input-field`, which it extends. ([#168](https://github.com/webtides/element-library/issues/168))

### description-list

- Fixed: the list looks the same on a page whose stylesheet takes the margin, the padding and the border off every element and off what an element generates (`*, ::before, ::after { margin: 0; padding: 0; border: 0 solid; }`, the reset of Tailwind CSS v4). The room of a row was a padding of the `<dt>` and the `<dd>` of the page, the gap between a name and its value a padding as well, and the line was moved to its place with a margin (`::slotted`). A rule of the page wins over such a rule, whatever its specificity and its cascade layer: the rows had no room, a name stood right under the line, and the line was drawn below its place. The room is the gap between the rows of the grid and the padding of the list now, the gap a column of the grid, and the line is placed with `translate`. The list takes nothing from the margin, the padding or the border of a `<dt>` or a `<dd>`. On a page without a reset it is the same to the pixel. ([#208](https://github.com/webtides/element-library/issues/208))
- Changed: a page that gave the room back itself, with a padding for the `<dt>`, the `<dd>` and the `<dd data-action>` in a list and a margin for the `::before` of a `<dt>`, takes those rules out, the ones for a wide list as well: a padding of the page adds to the room now, and the line would be drawn a row too high. ([#208](https://github.com/webtides/element-library/issues/208))
- Changed: `--el-description-list-term-width` is the width of the names alone: the gap to the values comes after it. It was inside of that width before, so a list with the property set has its values begin one gap (`--el-space-4`) later, and its names have that much more room. Unset, nothing changes: the names and the gap take 40% of the list at most, as before. ([#208](https://github.com/webtides/element-library/issues/208))
- Changed: a `<dt>` and a `<dd>` are as high as their text, and a `<dd data-action>` as high as one line where the list is wide as well: the room of the row is around them, not in them. A background the page gives one of them covers its text, not the row. ([#208](https://github.com/webtides/element-library/issues/208))
- Changed: a list whose rows are all hidden keeps the room above its first and below its last row, which is a padding of the list. A list with nothing in it has no height, as before. ([#208](https://github.com/webtides/element-library/issues/208))
- Added: `--el-description-list-padding-block` sets the room above and below a row, and `--el-description-list-gap` the gap between a name and its value and in front of an action. Unset, they are `--el-space-3` and `--el-space-4` as before. ([#208](https://github.com/webtides/element-library/issues/208))

### divider

- Added: a container can give its lines room: it names the room in a property that inherits (`--_el-context-divider-space`, internal), and the line has it in front of it and after it, above and below a horizontal line and at both sides of a vertical one. `el-menu` does so for a line between two entries. Outside of such a container a divider has no space around it, as before. ([#206](https://github.com/webtides/element-library/issues/206))

### file-field

- Added: `drop-message`: an area to drop a file onto, around the control, with that text in it. The control took a drop on its small button, and nothing invited one. While a dragged file is over the area it looks different, and the host has the state `dragover`. A click on the area opens the dialog; the keyboard is on the control in it. ([#197](https://github.com/webtides/element-library/issues/197))
- Added: a drop is a choice as one in the dialog: the control has the files, `input` and `change` are fired on it, and `input-change` reports them. A drop that `accept` or `multiple` refuses is not taken, the control keeps what it had, and the field says that the choice was not valid, with its `error-message`. ([#197](https://github.com/webtides/element-library/issues/197))
- Added: without JavaScript the area is a box with its text around the control of the browser, which posts the file with its form as before. ([#197](https://github.com/webtides/element-library/issues/197))

### input-field

- Added: content of the page at the start and at the end of the control: an element with `slot="start"` or `slot="end"` among the children of the field is taken into the control when the field renders. An icon, a unit, the start of an address, a button. It stands in a row with the input, whose text does not run under it, and follows the reading direction. The field moves the element of the page and does not copy it, and server-rendered markup has it in its place. ([#168](https://github.com/webtides/element-library/issues/168))
- Added: a click on a text or on an icon in the control puts the focus into the input; a button or a link there keeps its click and its stop of the Tab key. A text there is part of the description of the input (`aria-describedby`), so a unit is read with it; an icon and a button are not. ([#168](https://github.com/webtides/element-library/issues/168))
- Added: `clearable`: a button at the end of the control that empties the field. It shows while the field has a value and is not disabled, `input-change` reports the empty value, and the focus stays in the input. `clear-label` is its name (`Clear`). ([#168](https://github.com/webtides/element-library/issues/168))
- Added: with `styles/native.css` the control with its content is the control to the eye: the border, the surface and the focus ring are around all of it, as the border of a field that is not valid and the look of a disabled one, and it is as high as an input of its size alone. Without that file the content stands beside an input with the look of the browser. A field without content and without `clearable` renders its input alone, as before. ([#168](https://github.com/webtides/element-library/issues/168))
- Added: `maxlength` and `minlength` are passed on to the native `<input>`, in server-rendered markup as well, and one that is not set is not rendered. The control takes no more characters than `maxlength` while the user types, and a typed text that is shorter than `minlength` makes the field invalid the way `required` and `pattern` do, with its `error-message`. Set on the element they did nothing before. The fields that extend this one take both as well. ([#190](https://github.com/webtides/element-library/issues/190))

### list

- Added: `--el-list-gap` sets the gap between the start, the texts, the end and the control of a row. The rows read it, so it can be set on the list or for the page. ([#206](https://github.com/webtides/element-library/issues/206))

### list-item

- Fixed: what is in `end` keeps its width beside a title or a description that is longer than the row. It shrank together with the texts, down to next to nothing: on a phone a date broke after every character and stood as a column of ten lines, and an icon shrank to a sliver, or left its place and was drawn in the padding of the row where the page kept it from shrinking. It takes the width it has now, up to half of the row, and breaks after that, as the readme said. The ends of all rows of a list end on one line. ([#207](https://github.com/webtides/element-library/issues/207))
- Changed: a page that kept the end from shrinking itself (`el-list-item::part(end) { flex-shrink: 0 }`) does not need that rule any more. ([#207](https://github.com/webtides/element-library/issues/207))
- Fixed: the gap beside what is in `start`, `end` and `action` holds on a page whose stylesheet takes the margin off every element (`* { margin: 0 }`, the reset of Tailwind CSS v4). The row gave the gap to what the page slots in, as a margin (`::slotted`), and a rule of the page wins over such a rule, whatever its specificity and its cascade layer: the icon touched the title. The gap is one of the parts of the row now, and the row takes nothing from the margin, the padding or the border of what is slotted. A row without a `start` has no gap there, and a list without one in any row has no first column, as before. ([#206](https://github.com/webtides/element-library/issues/206))
- Changed: a page that gave the gap back itself, with a margin on what it slots into `start`, `end` and `action`, takes those rules out: a margin of the page adds to the gap now. ([#206](https://github.com/webtides/element-library/issues/206))
- Added: `--el-list-gap` sets the gap between the start, the texts, the end and the control of a row, on the list, on a row, or for the page. Unset, it is `--el-space-3` as before. ([#206](https://github.com/webtides/element-library/issues/206))

### menu

- Fixed: an `el-divider` between two entries has its room above and below on a page whose stylesheet takes the margin off every element (`* { margin: 0 }`, the reset of Tailwind CSS v4). The menu gave that room to the line as a margin (`::slotted`), and a rule of the page wins over such a rule: the line touched the entries. The menu names the room in a property that inherits now, and the line takes it in its own shadow root. ([#206](https://github.com/webtides/element-library/issues/206))
- Changed: a page that gave the room back itself, with a margin for an `el-divider` in a menu, takes that rule out: the margin adds to the room now. ([#206](https://github.com/webtides/element-library/issues/206))
- Changed: the panel is no part of a row of joined buttons: it stops the property that pulls a button over its neighbour there (`--_el-group-overlap`), as the ones for the corners and the line. ([#206](https://github.com/webtides/element-library/issues/206))
- Fixed: an open menu keeps the keyboard wherever the focus is. `Escape` closes it and gives the focus back to what it was opened for, and the key does not reach the page behind; `ArrowDown` and `ArrowUp` bring the focus to its first and to its last entry; the Tab key closes it, and the focus moves on from where it is. The menu heard its keys on its panel alone: an open menu whose entries did not have the focus was left with no key, and `Escape` closed what was behind it. It hears them at the window now, for as long as it is open. ([#202](https://github.com/webtides/element-library/issues/202))
- Fixed: a press on the heading of a group, on a line or on the padding of the panel leaves the focus on the entry that had it, and the arrow keys go on from there. The focus was nowhere in the page after such a press. Where no entry had the focus, the panel takes it itself: it has `tabindex="-1"`, and is no stop of the Tab key. ([#202](https://github.com/webtides/element-library/issues/202))
- Fixed: a menu that is open at a point closes when what it was opened for scrolls away under it: the page, or a region around the row, also one in a shadow root the row is slotted into (the content of an `el-app-frame`). The menu stayed where it was, over another row and with the actions of the first one. The focus goes back to what the menu was opened for without scrolling to it, so the scroll goes on. A scroll inside of a long menu, and one of a region that does not move the row, leave the menu open, and a menu at an element follows the element as before. ([#204](https://github.com/webtides/element-library/issues/204))
- Fixed: the button of a row closes the menu it has opened: a second press on the element the menu is open at closes it, and it stays closed, with the listener of the readme (`menu.showAt(button)` for a click) and nothing more. The press closed the menu when the pointer went down, as a press beside it, and the click of the same press opened it again: `menu-hide`, then `menu-show`, and a button that said `aria-expanded="true"` and could not collapse what it had expanded. The menu stays open now while the pointer is down on that element, and the `showAt()` that is called with the click closes it. A call with no press before it opens the menu as before. ([#203](https://github.com/webtides/element-library/issues/203))
- Fixed: a menu that is opened with `showAt()` is where it was opened while its own element is out of view, below a long list for example. It was at its own element instead, off the screen: the element was placed once before it had taken its place from `showAt()`, and that placement, which had to try the other side, was done after the right one. The panel is placed once it is shown now, and one placement at a time.
- Fixed: entries that the page renders after the menu has opened, and entries whose element is defined after it, get the focus once they are there: the first one, or the last one where `ArrowUp` has opened the menu. The menu is placed again for its new size. The focus stayed where it was, and a menu at a point kept the place of an empty panel. ([#202](https://github.com/webtides/element-library/issues/202))

### menu-item

- Added: `type`: an entry that sets something instead of doing something. With `type="checkbox"` it is on or off (`role="menuitemcheckbox"`), with `type="radio"` it is one of several of which one is chosen (`role="menuitemradio"`). `checked` is its state, which it says (`aria-checked`), also while it is off and while it is disabled. A page could put a mark into the `icon` slot before, and a screen reader heard nothing of it: the role of an entry is inside of its shadow root. ([#205](https://github.com/webtides/element-library/issues/205))
- Added: the state shows as a mark in front of the text, a check or a dot, in the new part `mark`. Its place is there while the entry is not checked as well, so the text does not move when the state changes. Where the user forces colours the mark has the colour of the text: the check is text, the dot is drawn with a border. ([#205](https://github.com/webtides/element-library/issues/205))
- Added: the page sets the state: the entry does not change `checked` when it is chosen, and the menu fires `menu-select` and closes as for every entry. The state is in the server-rendered markup. ([#205](https://github.com/webtides/element-library/issues/205))

## [0.4.0] - 2026-11-27

### accordion

- Changed: where scripting is off, a server-rendered accordion without `open="true"` is closed and cannot be opened; it was open before, because nothing had collapsed it. The readme has a rule for a page that wants the content readable there (`@media (scripting: none)` and the `content` part). ([#187](https://github.com/webtides/element-library/issues/187))
- Fixed: a closed accordion that was rendered on the server shows its header alone from the first paint. The markup of the server had the content as it is while open, the browser painted it, and the element took it away once it started: everything below the accordion jumped up with every page load, and where scripting is off the accordion was open. The stylesheet of the element now collapses the content unless the host has `open="true"`, which holds before the element starts. An accordion with `open="true"` is server-rendered open, with the line under its header and the turned chevron, and stays that way. ([#187](https://github.com/webtides/element-library/issues/187))
- Fixed: a closed accordion that is rendered in the browser starts closed. It was rendered open and collapsed with the transition, in front of the user and with the content below it moving. ([#187](https://github.com/webtides/element-library/issues/187))

### app-bar

- Added: `el-app-bar`, a new component: the bar at the top of a view, with a start (a button back, or the one for the navigation), a title and an end (the actions). Start and end follow the reading direction, and a region the page leaves empty takes no room. ([#178](https://github.com/webtides/element-library/issues/178))
- Added: the title is one line: what does not fit is cut with an ellipsis, and never pushes the actions out. The whole title stays in the page for assistive technology. `heading-level` (1 to 6) makes it the heading of the view; unset, it is text.
- Added: the buttons of the bar are plain while they have no appearance of their own; `appearance` names another one. The bar does not write to its buttons: it says the appearance in CSS properties that are inherited.
- Added: in the header of an `el-app-frame` the surface of the bar reaches as far as the surface of the region: under the status bar and the notch of a phone and to the sides of the screen, while its content stays clear of them. The line to the content is the one of the region there.
- Added: as high as a control and its padding, with and without a button, and at least `--el-touch-target` high on a touch screen.
- Added: a surface from `--el-color-bg` and a line to the content from `--el-color-border` and `--el-border-width`. The line is a border, which stays where the user forces colours and is there without a theme then. The bar is no landmark and has no role.

### app-frame

- Added: `el-app-frame`, a new component: the frame of an application. It fills what the browser shows and lays out five regions, a header, a footer, a navigation at the start side, an aside at the end side, and the content. A region the page leaves empty takes no room, and start and end follow the reading direction. ([#176](https://github.com/webtides/element-library/issues/176))
- Added: the frame is fixed to the edges of the viewport, which move with the address bar of a phone: it is as high as what the browser shows, and no higher. The content scrolls between the header and the footer, which stay in view. The window does not scroll in a frame; `scroller` is the element that does, for a page that sets the scroll back after a change of the view.
- Added: narrow and wide by its own width: from the width `wide-from` names (`30rem`, `40rem`, `48rem` by default, `64rem` or `80rem`) the navigation and the aside are columns beside the content, and each scrolls on its own. Below it the content and the aside are one column that scrolls, and the navigation is a drawer. The stylesheet decides, with a container query per step, so a server-rendered frame has its layout before the script has run. `wide` reads what the stylesheet has decided.
- Added: `--el-app-frame-navigation-size` (`16rem`) and `--el-app-frame-aside-size` (`20rem`) are the widths of the two columns.
- Added: the page writes the landmarks: `<header slot="header">`, `<nav slot="navigation" aria-label="…">`, `<main id="…">`, `<aside slot="aside">` and `<footer slot="footer">`. The frame adds none of its own.
- Added: the first stop of the Tab key is a link that skips to the content, with the text of `skip-label`. It is a link to the id of the `main` of the page, which works before the script has run. After it the content is in view from its start, the keys scroll it, and the Tab key goes on inside of it.
- Added: on a phone with `viewport-fit=cover` nothing in a region lies under the notch, the rounded corners or the home indicator. The surface of a region (`::part(header)`, `::part(footer)`, …) reaches the edge of the screen, and what is in it does not. A region tells the components in it how far its surface reaches, and that it draws the line to the content itself, in CSS properties that are inherited.
- Added: a region that scrolls and has nothing in it that takes the focus is a stop of the Tab key itself, so the keyboard can scroll it in every browser.
- Added: on paper the frame is as long as its content, which prints whole.
- Added: lines between the regions from `--el-color-border` and `--el-border-width`. They are borders, which stay where the user forces colours, and they are there without a theme then. Without a theme the frame paints nothing.
- Added: `narrow-only` and `wide-only` name the regions that are there at one width only (`header`, `navigation`, `aside`, `footer`, with a space between them): a bar of destinations in the footer of a phone, for example (`narrow-only="footer"`), or an aside for a desktop (`wide-only="aside"`). The stylesheet leaves a region out, without a script, and the frame keeps the edge of the screen clear that the region kept clear. ([#179](https://github.com/webtides/element-library/issues/179))
- Added: where the frame is narrow, the navigation does not show and opens as a drawer from the start edge. The page writes the navigation once: the element in the `navigation` slot is the column of the wide frame and the content of the drawer of the narrow one, and no node is moved. ([#177](https://github.com/webtides/element-library/issues/177))
- Added: any element with `data-navigation-toggle` in the frame opens and closes that drawer. The frame writes `aria-expanded` onto it, and it is not there where the navigation is a column: an `el-button` by the stylesheet of the frame, before any script has run, another element by the script (`hidden`).
- Added: the drawer is an `el-drawer`: modal, with the focus kept in it. `Escape`, its close button and a click beside it close it, and the focus goes back to the button that opened it. A link the user follows in it closes it, also where the page takes the click. `navigation-label` is its title and `close-label` the name of its close button; its parts are `drawer`, `drawer-header`, `drawer-title`, `drawer-close-button` and `drawer-body`.
- Added: a change of the width while the drawer is open leaves nothing behind: no backdrop, no lock on the scroll of the page and no inert page.
- Added: `navigation-open` opens and closes the drawer from a script, `app-frame-navigation-toggle` tells of both, and `:state(navigation-open)` matches while it is open.
- Added: `narrow-navigation="bar"`: where the frame is narrow, the navigation lies at the lower edge, over the footer, instead of being a drawer. For an `el-nav` in the `navigation` slot, whose destinations are a bar there and a rail in the column of the wide frame: the page writes them once. The region is a surface of the frame at the lower edge, as the footer is, and the column is as wide as what is in it. ([#181](https://github.com/webtides/element-library/issues/181))
- Added: the column of the navigation tells an `el-nav` in it to be a column (a rail, or the list its `column` asks for), and that the region draws the line to the content, in CSS properties that are inherited. The drawer of the navigation says the same.
- Added: `resizable` names the columns whose width the user sets by dragging their edge (`navigation`, `aside`). The edge is an `el-splitter` of the frame at the side of the column that faces the content: dragged with a mouse, a finger or a pen, a stop of the Tab key with the arrow keys, `Home` and `End`, and a separator with the width and the name of the column for assistive technology (`navigation-label`, and the new `aside-label`). Its parts are `navigation-splitter` and `aside-splitter`. ([#182](https://github.com/webtides/element-library/issues/182))
- Added: `navigation-size` and `aside-size` are the widths of the two columns in pixels. The frame sets them while the user drags, `app-frame-resize` tells of every width and `app-frame-resize-end` of the one that stays (`detail.region`, `detail.size`). The page keeps the width and gives it back in the attribute: the template writes it onto the grid, so a server-rendered frame has it before the script has run.
- Added: `--el-app-frame-navigation-min-size`, `--el-app-frame-navigation-max-size`, `--el-app-frame-aside-min-size` and `--el-app-frame-aside-max-size` are the limits of a column that is resizable (`10rem`, and `min(30rem, 40cqi)`: two fifths of the width of the frame at most). The stylesheet holds a width that is kept between them.
- Added: where the frame is narrow, a column has no edge to drag, and the drawer of the navigation keeps the width of the stylesheet.
- Added: a view of columns in the content: a list and what is chosen in it beside each other, each scrolling on its own where the frame is wide, and a page that scrolls as a whole where it is narrow. The frame does it as it is: the region of the content has a height where the frame is wide, and the frame is a container for the queries of the page. The readme says what the page writes, and tests and a story hold it. ([#200](https://github.com/webtides/element-library/issues/200))

### toolbar

- Added: `el-toolbar`, a new component: the row of controls over a list or a view. A toolbar for assistive technology (`role="toolbar"`, named by `label`), with what the page writes into it as its controls: `el-button`, `el-button-group`, `el-segmented-field`, and `el-divider` between two groups. `size` and `appearance` are the size and the appearance of the controls that have none of their own: of every `el-button` in the toolbar, also inside of a group, and `size` of an `el-segmented-field`. A toolbar that names none has controls of the medium size and plain buttons. A control that names its own keeps it, the defaults included. The toolbar does not write to its controls: it says both in CSS properties that are inherited. The controls stand in a row with a gap of `--el-space-2`. What is slotted into `end` stands at the end; start and end follow the reading direction. A toolbar with more controls than its width takes breaks into a second line. One stop of the Tab key, as the WAI-ARIA toolbar pattern says: the arrow keys move the focus between the controls and around the ends, Home and End go to the first and the last one, and Tab leaves the toolbar and comes back to the control that had the focus last. The options of an `el-segmented-field` are controls of the toolbar: the left and right arrow keys go through them, Space and the up and down keys choose. In a control that takes text the keys belong to that control. An `el-button` with an `aria-label`, a button with an icon alone, shows that name as a tooltip, for the pointer and for the focus of the keyboard. The tooltips are `el-tooltip` elements in the shadow root of the toolbar (`::part(tooltip)`); the toolbar imports the tooltip, and with it `@floating-ui/dom`. The look is the stylesheets alone: a server-rendered toolbar does not change when the elements take over. The script adds the keyboard and the tooltips. ([#194](https://github.com/webtides/element-library/issues/194))

### tooltip

- Added: `anchor`: the anchor as an element, for one that an id cannot name: an element in another tree than the tooltip, the light DOM of a component whose shadow root the tooltip is in. A property only, and it comes before `for`. ([#194](https://github.com/webtides/element-library/issues/194))
- Added: `type` (`'description'` by default, or `'label'`): a tooltip of the type `label` shows the name its anchor already has, of a button with an icon alone for example. It does not describe the anchor (`aria-describedby` is not written) and is hidden from assistive technology, which would read the name twice. ([#194](https://github.com/webtides/element-library/issues/194))
- Fixed: in Safari a tooltip could stay shown after its anchor had lost the pointer or the focus: `open` was `false`, and the tooltip was still there. The tooltip read its own state back (`states.has('open')`) to know whether there was something to close, and WebKit forgets what was added to the states of an element a moment later, while `:state(open)` still matches. The tooltip keeps a field of its own now.

### tree

- Added: `el-tree`, a new component: entries that open and close, for folders, categories and a library beside the content. The tree is a list (`role="list"`, named by `label`), every `el-tree-item` in it is an entry, and an entry holds the entries below it, to any depth. To assistive technology it is nested lists of links with a button per branch, not a `role="tree"`: the entries stay links, and they work before the script has run. The readme says why. The keys of the WAI-ARIA tree view pattern, on top of the Tab key: up and down between the entries that are shown, right opens a branch or goes into it, left closes it or goes to the entry above, Home and End. The other way round for left and right in a text that runs from right to left. `--el-tree-indent` is how far the entries of a level stand in from the ones above, `--el-space-4` unset. The tree keeps no state: which branches are open is the `open` attribute of the entries. `tree-item-toggle` of an entry bubbles through the tree. ([#193](https://github.com/webtides/element-library/issues/193))

### tree-item

- Added: `el-tree-item`, a new component: one entry of an `el-tree`, an item of its list (`role="listitem"`), with the entries below it in a list of their own. It has an icon at the start (`start` slot), its name (`label`, or the `label` slot) and a count at the end (`end`). With `href` the name is a native link whose target is the whole row. An entry that also has entries below it gets a button that opens and closes them, named by the name of the entry, with `aria-expanded`. Without `href`, an entry with entries below it is that button as a whole. `open` is the state of a branch, reflected to the attribute. The stylesheet reads the attribute: a server-rendered entry shows its entries, or hides them, from the first paint. The button, the arrow keys and `toggle()` change it and fire `tree-item-toggle`; setting `open` from a script fires nothing. `current` marks the entry of the page the user is on: `aria-current="page"`, a tint, a bar at the start in the accent colour and a heavier name. The bar is a border, so it stays where the user forces colours. A row is as wide as the tree on every level, and what stands in it is moved in by `--el-tree-indent` per level. A long name breaks, inside of a word where it has to. On a touch screen a row is at least `--el-touch-target` high, and the button of a branch that wide and high. ([#193](https://github.com/webtides/element-library/issues/193))

### avatar

- Added: `el-avatar`, a new component: the picture that stands for a person or a thing. It shows the first of these that it has: the `image`, the `initials`, an icon (the `icon` slot, and the outline of a person without it). An image that cannot be loaded makes way for the next, also when it had failed in server-rendered markup before the element was there. With a `label` the avatar is an image with that name for assistive technology; without one it is hidden, as a decoration beside a name that is written out. `shape` is `circle` (the default), `square` or `rounded`, and `size` is `small`, `medium` or `large`, both reflected: the width and the height of an avatar are the control height of its size, and `--el-avatar-size` makes it any other size. The background is an eighth of the text colour, so the avatar shows on any background and without a theme. ([#79](https://github.com/webtides/element-library/issues/79))

### badge

- Added: `el-badge`, a new component: a short label that marks something with a status or a count ("New", "3"). Pure presentation, without a role and without behaviour. It has the `variant` and the `appearance` of the shared vocabulary, both reflected, `pill` for fully rounded ends and `pulse` for a ring that spreads from the badge to catch the eye; the pulse stands still for a user who prefers reduced motion. A badge is three quarters of the font size of the text it stands in, so it has no `size`. With a single character it is as wide as it is high: a square, and a circle as a pill. ([#74](https://github.com/webtides/element-library/issues/74))

### breadcrumb

- Added: `el-breadcrumb`, a new component: the trail from the start page to the current page. A `nav` landmark, named by `label` ("Breadcrumb" by default), that holds a list; every `el-breadcrumb-item` slotted into it is an entry of that list. The entries stand in a row that breaks into a second line where it does not fit, and a line after the first starts with a separator. `--el-breadcrumb-separator`, a CSS string (`'/'` by default), is what stands between two entries: set on the breadcrumb or for the whole page, it is the separator of every entry. The breadcrumb does nothing with its entries from a script, so a server-rendered trail is complete without JavaScript. ([#123](https://github.com/webtides/element-library/issues/123))

### breadcrumb-item

- Added: `el-breadcrumb-item`, a new component: one entry of an `el-breadcrumb`, an item of its list (`role="listitem"`). With `href` it is a native link (`target` is passed on, `rel` is written with it), without it is text. `current` marks the entry of the page the user is on: `aria-current="page"`, the text colour of the theme and a heavier weight, as text or as a link. Every entry but the first shows the separator in front of itself, in the muted text colour of the theme and hidden from assistive technology. A link has the accent colour of the theme, the text colour without a theme, is underlined under the pointer and shows the focus ring of the theme; on a touch screen it is at least `--el-touch-target` wide and high. ([#123](https://github.com/webtides/element-library/issues/123))

- Fixed: Enter in a field submits a form whose submit button is an `el-button`, with any number of fields. Before, only a form with a single field was submitted: the platform found no submit button in the form. ([#113](https://github.com/webtides/element-library/issues/113))

- Fixed: without a theme, the keyboard focus of `el-button` can be seen on every page. ### button-group

- Added: `el-button-group`, a new component: a row of `el-button` that reads as one control, the actions of a toolbar, a button with a second one for more options. A group to assistive technology (`role="group"`), named by `label`. The buttons touch and share the border between them; the corners that face a neighbour are square, the outer corners of the row keep the radius of the buttons, and the row is mirrored in a text that runs from right to left. Two filled buttons are divided by a line, a quarter of the text colour on the fill. The button that has the focus lies over its neighbours, so its focus ring is not covered. A button inside of a slotted element is joined as that element is, which makes the anchor of an `el-popover` a part of the row; what is in the panel of the popover is not. The group joins its buttons with its stylesheet alone: it runs no script on them, and a server-rendered group does not change when the elements take over. ([#124](https://github.com/webtides/element-library/issues/124))

### card

- Added: `el-card`, a new component: a surface that groups what belongs together, a form, a section of settings, an entry of a list. Pure presentation, without a role and without behaviour. It has four regions, each of them a slot: `media` at the top, then `header`, the body and `footer`; a region that nothing is slotted into takes no space, on the server as in the browser. `appearance` is `outlined` (the default: a surface in `--el-color-bg` with a border and the shadow `--el-shadow-md`), `filled` (the muted fill) or `plain` (nothing painted), reflected. `--el-card-padding` is the padding of the header, the body and the footer; unset, it is `--el-space-4`. A card fills the height its container gives it, so cards that a grid stretches are equally high and their footers are in one line. ([#76](https://github.com/webtides/element-library/issues/76), [#81](https://github.com/webtides/element-library/issues/81))

### checkbox-group-field

- Added: `el-checkbox-group-field`, a new component: a choice of any number of options, the group of checkboxes that `el-radio-field` is for radios. A native `<fieldset>`/`<legend>` wrapping one `<input type="checkbox">` per entry of `options`, all under one name, with the label, the help message, the error message and the layout of every field. `value` is the list of the checked values, in the order of the options: an array from a script, JSON as an attribute. ### color-field

### combobox-field

- Added: `el-combobox-field`, a new component: a text the user writes, with suggestions the browser offers while they type. ### copy-button

- Added: `el-copy-button`, a new component: a button that copies a text to the clipboard and says whether that worked. ### date-field

- Added: `el-date-field`, a new component: a date, a time or both, entered in the control of the browser and picked in its picker. ### dialog

- Changed: on a touch screen (`@media (any-pointer: coarse)`) the close button is at least `--el-touch-target` wide and high (20 × 20 px before). Its icon keeps its size, and the header grows with the button. Unchanged on a fine pointer and without the token.
- Fixed: a dialog that is taken out of the page while it is open gives the page its scrolling back. Before, the page stayed locked (`overflow: hidden` on the document) with no dialog left to close, and a dialog opened later did not unlock it either, because the lock counts its holders. Put back into the page while `open`, the dialog opens as a modal again; before, it was shown in the flow of the page, without a backdrop and without taking the focus.

The footer was meant to be left out without content, but the rule for it never matched, so a dialog without a footer had the padding of the footer (`--el-space-4`, 16 px with the shipped themes) as extra room under its body. A footer that gets content later appears with it, and the footer of a server-rendered dialog is shown.
- Changed: `dialog-after-show` and `dialog-after-hide` fire only when the dialog has got there. A way that is cut short has none, so after `dialog-show` comes `dialog-after-show` or `dialog-hide`, and after `dialog-hide` comes `dialog-after-hide` or `dialog-show`; before, `dialog-after-show` could fire after the dialog had closed again. The promises of `show()` and `hide()` resolve when the dialog is at rest, at whichever end, and never reject; a `show()` while the dialog is still coming in waits for that way, where it resolved at once. Two changes of `open` before the next frame that cancel each other do nothing and fire nothing. Nothing changes for a dialog that opens and closes undisturbed. ([#110](https://github.com/webtides/element-library/issues/110))
- Fixed: opening and closing in quick succession no longer leaves the dialog out of step with `open`. A dialog that was closed and opened again while its way out was still running stayed closed with `open` still `true`: nothing was shown, the promise of `show()` never resolved, and the next `show()` did nothing. A button that toggles the dialog and is clicked twice got there. A dialog that was opened and closed again at once kept the class of its shown state, and came in without its transition the next time. Now the last value of `open` wins: a dialog that is closed on its way in turns back, one that is opened on its way out turns round and is shown again. ([#110](https://github.com/webtides/element-library/issues/110))
- Fixed: a `<form method="dialog">` inside the dialog closes it, as the readme has said since 0.1.0. It never did: the form is a child of the element and the `<dialog>` is in the shadow root, so the platform found no dialog above the form to close. The dialog now closes for the `submit` of such a form itself: by its submit button, by `Enter` in one of its fields, by a button that belongs to it through the `form` attribute, and by a button with `formmethod="dialog"` in a form with another method. It closes without `dialog-request-close`; a listener that calls `preventDefault()` on the `submit` keeps it open, and so does a form that is not valid. There is no `returnValue`: the button that was used is `event.submitter` in the listener. ([#111](https://github.com/webtides/element-library/issues/111))
- Fixed: `show()` and `hide()` wait for the dialog also when `open` got its value just before the call, in the same frame: set by hand, or by `requestClose()`. Such a call resolved at once, while the dialog was still shown (or still closed), because the dialog begins to move with the next frame. ([#112](https://github.com/webtides/element-library/issues/112))

### empty-state

### pagination

### popover

- Added: `el-popover`, a new component: a panel that floats next to an anchor. A click on the anchor opens it; a second click, a click beside it or `Escape` closes it. It is built on the native popover of the platform (`popover="auto"`), so the panel is in the top layer, where nothing clips it or lies on top of it, and one popover is open at a time. `placement` names the side of the anchor (`top`, `bottom`, `left`, `right`, each also with `-start` or `-end`), `distance` the gap, and `arrow` adds an arrow that points to the anchor. The panel goes to the opposite side when it has no room, stays inside the viewport, and follows its anchor while it is open. `open` is reflected and has the `open` custom state; `show()`, `hide()` and `toggle()` do the same from a script, and `popover-show` and `popover-hide` fire for every way of opening and closing. The anchor gets `aria-expanded`, and `Escape` gives the focus back to the anchor when it was inside the panel. Needs the Popover API: Chrome 114, Firefox 125, Safari 17. ([#70](https://github.com/webtides/element-library/issues/70))

- Fixed: the group no longer throws when it connects before `el-tab-link` is defined (`TypeError: Cannot read properties of undefined (reading 'states')`), and the first selection reaches the links all the same. ([#99](https://github.com/webtides/element-library/issues/99))
- Fixed: with no `selected` and panels that are not defined yet, the first panel is selected. The group read the `name` property, which a panel only has once it is defined, so every panel stayed hidden; it reads the attribute now. ([#99](https://github.com/webtides/element-library/issues/99))
- Fixed: links and panels that are added to the group later are taken in: they get their states, a new panel is labelled by its link, and a group that had no panel at first selects the first one that comes. Before, the group looked for its parts once, when it connected. ([#99](https://github.com/webtides/element-library/issues/99))

- Changed: the link sets its `active` state itself, while it has `aria-selected="true"`. Before, the `el-tab-group` set the state from outside, which failed when the link was not defined yet. ### tab-panel

- Added: the panel has `role="tabpanel"`, and its `el-tab-group` labels it by its link (`aria-labelledby`). A role the page sets itself is kept. ([#97](https://github.com/webtides/element-library/issues/97))

### tag

- Added: `el-tag`, a new component: a label for one of several things that belong to something, a keyword or a filter that is set. A tag is 0.7 times as high as a control of the same size, so that it fits into a field. `removable` renders a remove button that fires `tag-remove`; the tag does not remove itself, the page decides what removing means. ### tag-field

- Added: `el-tag-field`, a new component: a list of short texts the user writes, such as keywords or recipients. Enter adds the text of the input, and so does a comma, typed or pasted. `value` is the list; in a form every entry is submitted under the `name` by a hidden input. ### textarea-field

- Added: `autocomplete`, `inputmode`, `enterkeyhint`, `autocapitalize`, `autocorrect` and `spellcheck` are passed on to the native `<textarea>`, in server-rendered markup and on every render. - Fixed: a server-rendered `el-textarea-field` shows its value before its JavaScript runs, and without JavaScript. Known limit: a line break at the very start of the value is missing until the element has started, because the HTML parser drops a line break that directly follows `<textarea>`.
- Fixed: a re-render no longer overwrites text typed since the last change the field has seen. Before, every render wrote `value` back into the control: a required field renders right after it gets the focus, and text that arrived then was gone. ([#100](https://github.com/webtides/element-library/issues/100))
- Fixed: `value` follows the textarea on every `input`. Text that arrives without a key going up is the value of the field at once and is reported with `input-change`: a paste with the mouse, dictation, a suggestion of an on-screen keyboard, a script that fills the field. Before, the field read the textarea on `keyup` and `change` only: it did not know such text until the field was left, and a required field counted as not valid for that long. ([#100](https://github.com/webtides/element-library/issues/100))
- Fixed: the mark of a touched field (✓ or ✗) stands beside the textarea, at its top, and has the colours it has beside an input (`--el-color-success`, `--el-color-danger`). - Fixed: `aria-describedby` on the textarea now names the help message. It pointed at `<name>-help`, an id that does not exist.
- Fixed: the error message is announced by screen readers: it is an alert (`role="alert"`), and the textarea names it in `aria-describedby` while it is shown. Before, nothing connected the message with the textarea. ([#94](https://github.com/webtides/element-library/issues/94))
- Fixed: the cross of a field that is not valid empties `value` as well, reports it with `input-change`, and `valid` follows the empty textarea. Before, only the textarea was emptied. See `form-field`. ([#115](https://github.com/webtides/element-library/issues/115))
- Fixed: the error message has the danger colour of the theme (`--el-color-danger`). - Fixed: the textarea says whether the field is valid (`aria-invalid`). Before, the error message reached a screen reader and the state of the control did not, while the control of `el-input-field` and of `el-select-field` has said it all along. ([#133](https://github.com/webtides/element-library/issues/133))

### toast

- Added: `el-toast`, a new component: the region of a page where toasts appear. A toast is an `el-notification`; the region gives it its place at an edge of the viewport (`placement`: `top-start`, `top`, `top-end` as the default, `bottom-start`, `bottom`, `bottom-end`) and puts several of them into a stack. `toast(message, options)` shows a text, a node or an `el-notification` as a toast and returns the notification; it is a method of the element and a function of the module (`import { toast } from '@webtides/element-library/toast'`), which uses the first `el-toast` of the document and adds one when there is none. A text or a node becomes a notification that can be closed and leaves after five seconds; the options `variant`, `duration`, `closable` and `closeLabel` change that. With `max` no more than that many toasts show at once: the rest wait in the order they came and are shown when a place is free. While it has toasts the region is a native popover in the top layer, above everything of the page, and lets the pointer through beside and between them; without toasts it is not shown. The stack is a landmark with the name in `label`, and `--el-toast-inset` is its distance from the edges of the viewport. ([#72](https://github.com/webtides/element-library/issues/72))

### tooltip

- Added: `el-tooltip`, a new component: a short text that explains another element, its anchor. It stands next to the anchor in the page and names it by id with `for`, the way a `<label>` names its field. It opens while the pointer rests on the anchor (after `show-delay`, 150 ms by default) or while the anchor has the focus of the keyboard (at once), and closes when they leave (after `hide-delay`) or with `Escape`. The pointer can go from the anchor onto the text without the tooltip closing. A finger opens nothing. The tooltip is the description of its anchor for a screen reader (`aria-describedby`), open or closed, also for an `el-button`, and has the role `tooltip`. The element is a native popover (`popover="manual"`) in the top layer, placed with `placement` (`top` by default), `distance` and an optional `arrow`, like `el-popover`; it changes sides without room and stays inside the viewport. `open` (reflected, with the `open` custom state), `show()` and `hide()` open and close it from a script, `disabled` leaves it to the script alone, and it fires `tooltip-show` and `tooltip-hide`. Without a theme it has the system colours the other way round. ([#71](https://github.com/webtides/element-library/issues/71))

## [0.2.0] - 2026-06-10

### Packaging

- Added: a new `@webtides/element-library/catalog` export — the recommended way to consume this library under **server-side rendering** with `@webtides/element-js-ssr-renderer`. `catalog.js` is a generated, bundler-traceable `Catalog` (`{ "el-button": () => import("./src/components/button/button.js"), … }`) covering all 26 components. Because it ships **inside the package**, its specifiers are package-internal relative paths that resolve in any consumer's bundle regardless of `node_modules` layout, so SSR works on every target (plain Node, Nitro, edge/Workers, webpack, Vite) with no consumer codegen and no hand-written import map: `import catalog from "@webtides/element-library/catalog"` then pass it to the renderer's `resolve`. Distinct from `./all` (a client-side side-effect bundle that registers every component for hydration) — the catalog defines nothing and runs no `define()`, it only tells the SSR renderer how to load each class. Regenerated automatically on release via the `prepack` hook (and on demand with `npm run gen:catalog`), so it can never drift from the components; a Node SSR smoke test (`npm run test:catalog`, run in CI) verifies a known tag still resolves to its class through the renderer.
