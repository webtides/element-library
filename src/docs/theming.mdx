# Theming

`@webtides/element-library` is intentionally **headless by default** — components render with minimal structural CSS and no opinionated visual identity. When you want a coherent visual look, you opt into a theme.

A theme is an **opt-in CSS file** that sets the library's `--el-*` design tokens at `:root`. Components pick up the tokens automatically, with safe null-ish fallbacks if no theme is loaded.

Try it live: use the **Theme** dropdown in the Storybook toolbar to flip between `None (headless)`, `Default`, `High contrast`, and `Sketchy`. Pair it with the **Color scheme** dropdown to see how the themes adapt to light/dark.

## Quick start

Import a shipped theme once, at the top of your app, and the stylesheet that decorates native form controls with its tokens:

```js
// A theme: pick one
import '@webtides/element-library/themes/default.css';
// import '@webtides/element-library/themes/high-contrast.css';

// The look of the inputs, textareas and selects of the library's fields
import '@webtides/element-library/styles/native.css';
```

The theme sets the tokens, and every component on the page picks them up. No per-component setup, no class on `<html>` required.

`native.css` gives the native control of a field its border, radius, padding and focus ring: the input of `el-input-field` and `el-password-field`, the textarea of `el-textarea-field` and the select of `el-select-field`. Native controls of the page that are not in a field are not touched. Leave it out and the controls of the fields keep the look of the browser, while everything else follows the theme.

If you want to stay headless, **import neither**. Components keep working; they just render with the browser-native form-control look and no decorative borders, backgrounds, or shadows.

## Themes vs. color schemes

These are two separate axes:

- A **theme** is a visual identity — palette, motion, radii, spacing. The library currently ships three: `default`, `high-contrast`, and `sketchy`. You can write your own.
- A **color scheme** is light vs. dark, set by the user or the page via the CSS `color-scheme` property.

The shipped themes use the [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark) function, so **a theme carries both modes**. Switching `color-scheme` flips between the light and dark variants of whichever theme is active. You don't ship a "dark theme" — you ship a theme, and the user's color-scheme picks the mode.

```html
<!-- Follow the OS / user agent -->
<html style="color-scheme: light dark">
    …
</html>

<!-- Force one mode regardless of OS preference -->
<html style="color-scheme: dark">
    …
</html>
```

The `default.css` and `high-contrast.css` themes both declare `color-scheme: light dark` themselves, so without further configuration on your page, both modes work out of the box.

### Other user preferences

The shipped themes also respond to two other user-preference media queries:

- **`prefers-reduced-motion: reduce`** — `--el-duration-md` collapses to `0s` in both themes, disabling component transitions.
- **`prefers-contrast: more`** — the default theme bumps `--el-color-fg` and `--el-color-border` to pure black/white, raises `--el-border-width` to `2px` and `--el-focus-ring-width` to `3px`. The high-contrast theme is already at its contrast ceiling, so it doesn't change.

If you write a custom theme, mirror these media queries in your file. They're CSS-level rules, not part of the token API, so you opt in by including them.

## What you can theme

Three layered surfaces, in increasing specificity:

| Surface              | What it is                                                             | When to use it                                                 |
| -------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| **Design tokens**    | CSS custom properties (`--el-*`) read by every component's stylesheet. | Primary surface. Covers ~90% of theming needs.                 |
| **CSS Shadow Parts** | Named slots in each component's shadow tree (`::part(name)`).          | When you need to override structure that tokens can't express. |
| **Custom states**    | Host-level `:state(name)` selectors that mirror component state.       | State-aware styling (`:state(open)`, `:state(active)`, etc.).  |

Tokens are documented below. Parts and states are listed in each component's docs page (CSS Parts and "States" sections).

## Token reference

All tokens use the `--el-` prefix. Component CSS reads them with null-ish fallbacks (`0` widths, `transparent` colors, `none` shadows), so unthemed = headless.

### Color — surfaces & text

| Token                 | Default value (light / dark) | Used for                             |
| --------------------- | ---------------------------- | ------------------------------------ |
| `--el-color-fg`       | `#111827` / `#f3f4f6`        | Primary text & icons.                |
| `--el-color-fg-muted` | `#6b7280` / `#9ca3af`        | Help text, inactive labels.          |
| `--el-color-bg`       | `#ffffff` / `#0f1115`        | Default surface background.          |
| `--el-color-bg-muted` | `#f3f4f6` / `#1c1f24`        | Subdued surfaces, hover backgrounds. |
| `--el-color-border`   | `#d1d5db` / `#2d3138`        | Default border / divider color.      |

### Color — interactive & semantic

| Token                   | Default value (light / dark) | Used for                                                       |
| ----------------------- | ---------------------------- | -------------------------------------------------------------- |
| `--el-color-accent`     | `#2563eb` / `#60a5fa`        | Brand / interactive accent. The colour of the `brand` variant. |
| `--el-color-success`    | `#16a34a` / `#4ade80`        | Validity OK indicators. The colour of the `success` variant.   |
| `--el-color-warning`    | `#f59e0b` (both)             | The colour of the `warning` variant.                           |
| `--el-color-danger`     | `#dc2626` / `#f87171`        | Validity error indicators. The colour of the `danger` variant. |
| `--el-color-focus-ring` | `var(--el-color-accent)`     | Focus outline color.                                           |

`--el-color-warning` is one value for both colour schemes. A warning fill carries dark text, so the colour has to stay light; where it is the text itself, on the page background, a component mixes it half and half with `--el-color-fg`.

### Variants, appearances and sizes

Components that carry a meaning in their colour share one vocabulary for it. `el-button` speaks all of it; `el-badge` has the `variant` and the `appearance`, and takes its size from the text it stands in; `el-input-field` and `el-password-field` have the `size`, which shows once `native.css` decorates their control. `el-spinner` has the `size` as well, as a factor on the font size that it takes its size from.

| Attribute    | Values                                                       | What it picks                                                           |
| ------------ | ------------------------------------------------------------ | ----------------------------------------------------------------------- |
| `variant`    | `neutral` (default), `brand`, `success`, `warning`, `danger` | The colours, see the table below.                                       |
| `appearance` | `filled` (default), `outlined`, `plain`                      | How they are painted: as a fill, as a border and text, or as text only. |
| `size`       | `small`, `medium` (default), `large`                         | The height, the paddings and the font size.                             |

A theme does not set anything per appearance or per size: one colour per variant is enough, and the sizes derive from `--el-control-height`, the spacing scale and the two font sizes.

| `variant` | Fill                                                        | Text on the fill    | Border and text without a fill                            |
| --------- | ----------------------------------------------------------- | ------------------- | --------------------------------------------------------- |
| `neutral` | `--el-color-bg-muted`, with a border in `--el-color-border` | `--el-color-fg`     | `--el-color-border` and `--el-color-fg`                   |
| `brand`   | `--el-color-accent`                                         | `--el-color-bg`     | `--el-color-accent`                                       |
| `success` | `--el-color-success`                                        | `--el-color-bg`     | `--el-color-success`                                      |
| `warning` | `--el-color-warning`                                        | a fixed dark colour | `--el-color-warning`; the text mixed with `--el-color-fg` |
| `danger`  | `--el-color-danger`                                         | `--el-color-bg`     | `--el-color-danger`                                       |

The text on a brand, success or danger fill is `--el-color-bg`: these colours are dark in a light scheme and light in a dark one, and the background colour is the other way round.

The three attributes are on the host, so a stylesheet can select them: `el-button[variant='danger']`, `el-button[appearance='plain']`.

| `--el-space-3` | `0.75rem` |
| `--el-space-4` | `1rem`    |

### Radius & border

| Token               | Default (default theme / high-contrast) | Used for                                   |
| ------------------- | --------------------------------------- | ------------------------------------------ |
| `--el-radius-sm`    | `2px` / `0`                             | Small inset elements (checkbox indicator). |
| `--el-radius-md`    | `6px` / `2px`                           | Inputs, buttons.                           |
| `--el-radius-lg`    | `12px` / `4px`                          | Panels, popovers, future modals/cards.     |
| `--el-border-width` | `1px` / `2px`                           | Default border width.                      |

### Typography

| Token               | Default                                                          |
| ------------------- | ---------------------------------------------------------------- |
| `--el-font-family`  | `ui-sans-serif, system-ui, -apple-system, 'Segoe UI', Roboto, …` |
| `--el-font-size-sm` | `0.875rem`                                                       |
| `--el-font-size-md` | `1rem`                                                           |
| `--el-line-height`  | `1.5`                                                            |

### Shadow

| Token            | Default theme               | High-contrast theme |
| ---------------- | --------------------------- | ------------------- |
| `--el-shadow-md` | `0 4px 12px light-dark(…)`  | `none`              |
| `--el-shadow-lg` | `0 12px 24px light-dark(…)` | `none`              |

`--el-shadow-lg` is used by floating surfaces (`el-dropdown`'s panel and `el-dialog`'s panel; future popovers). `--el-shadow-md` is part of the contract for inline elevation but isn't read by any current component — set it in your theme to ready it for future surfaces or your own overrides.

### Motion

| Token              | Default theme                | High-contrast theme |
| ------------------ | ---------------------------- | ------------------- |
| `--el-duration-md` | `200ms`                      | `150ms`             |
| `--el-ease`        | `cubic-bezier(0.2, 0, 0, 1)` | same                |

### Focus ring & sizing

| Token                    | Default theme | High-contrast theme |
| ------------------------ | ------------- | ------------------- |
| `--el-focus-ring-width`  | `2px`         | `3px`               |
| `--el-focus-ring-offset` | `2px`         | `2px`               |
| `--el-control-height`    | `2.5rem`      | `2.75rem`           |
| `--el-touch-target`      | `2.75rem`     | `3rem`              |

`--el-control-height` is the minimum height of the text fields, the select and a medium `el-button`; a small button is 0.8 times, a large one 1.25 times as high.

`--el-touch-target` is the smallest size a control may have where a finger operates it. It takes effect on a touch screen, that is under `@media (any-pointer: coarse)`: there no control of the library is smaller than the token in either direction.

- A control with a shape of its own grows to that size: `el-button` in every size and shape (a circle stays round), the text fields and the select, the buttons and the input of `el-amount-field`, the arrows of `el-slider` and `el-carousel`, `el-tab-link` and the header of `el-accordion`.
- A control that is an icon or a glyph grows around it: the password toggle, the clear cross of an invalid field, the close buttons of `el-dialog` and `el-notification`, the dots of `el-slider`.
- The label of `el-checkbox-field`, `el-switch-field` and of every option of `el-radio-field` is the hit area and gets that size.
- The bullets of `el-carousel` keep their size. Each gets a hit area of that size around its dot, and the bullets move apart by as much.

With a mouse or trackpad alone the sizes follow `--el-control-height` and the paddings. `el-amount-field` is the one exception: the height of its buttons follows `--el-touch-target` on every pointer. `any-pointer: coarse` also matches a laptop with a touch screen.

Without the token, as in the headless default, the sizes stay as they are on a touch screen too. A theme of your own only has to set `--el-touch-target` to get these sizes.

`el-button` also knows the difference in its states: its hover styles only apply where the pointer can hover (`@media (hover: hover)`), because a touch screen leaves `:hover` on the button after a tap. A pressed button (`:active`) is darkened on every pointer.

### Component tokens

A few components add their own tokens on top of the shared vocabulary above. They have null-ish or sensible fallbacks, so they're optional — set them in a theme to tune that component.

| Token                            | Default theme                                                | Fallback (headless)                            | Used by                                                                   |
| -------------------------------- | ------------------------------------------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------- |
| `--el-dialog-width`              | `31rem`                                                      | `31rem`                                        | `el-dialog` panel width.                                                  |
| `--el-dialog-overlay-background` | `rgba(17, 24, 39, 0.5)` (dark scrim)                         | `transparent`                                  | `el-dialog` `::backdrop` (the overlay scrim).                             |
| `--el-dialog-enter-offset`       | _(unset)_                                                    | `0.5rem`                                       | Vertical distance the dialog animates in from.                            |
| `--el-select-indicator-color`    | _(unset)_; the high-contrast theme sets `var(--el-color-fg)` | `var(--el-color-fg-muted)`                     | The chevron of `el-select-field`, once `native.css` decorates the select. |
| `--el-spinner-indicator-color`   | _(unset)_                                                    | `var(--el-color-accent)`, then the text colour | The quarter of `el-spinner` that turns.                                   |
| `--el-spinner-track-color`       | _(unset)_                                                    | a fifth of the text colour                     | The ring of `el-spinner`.                                                 |

Because the overlay scrim falls back to `transparent`, an **unthemed** `el-dialog` has no visible backdrop — it stays headless like every other component. Import a theme (or set `--el-dialog-overlay-background` yourself) to get the dimmed background.

## Writing your own theme

A theme is just a CSS file that sets the tokens you care about — you only need to override what you want to change. It needs no rules for form controls: with `styles/native.css` loaded, your tokens reach them as well. Anything you leave out falls back to the component's null-ish default (or to whatever theme is layered before yours).

```css
/* my-app/src/themes/sunset.css */

:root {
    color-scheme: light dark;

    /* Take the default's surfaces and just override accent + radii */
    --el-color-accent: light-dark(#e25b30, #ffb88a);
    --el-color-focus-ring: var(--el-color-accent);

    --el-radius-sm: 4px;
    --el-radius-md: 10px;
    --el-radius-lg: 20px;

    --el-duration-md: 250ms;
}
```

```js
// my-app/src/main.js
import '@webtides/element-library/themes/default.css'; // tokens you keep
import './themes/sunset.css'; // overrides
```

You can also stack themes — load `default.css` first as a baseline, then a scoped override sheet for a specific subtree.

### Scoping a theme to a subtree

Themes don't have to live at `:root`. Drop the tokens on any element to scope them:

```html
<body>
    <main>Default theme everywhere…</main>

    <section
        style="
        --el-color-accent: #16a34a;
        --el-radius-md: 0;
    "
    >
        …except inside this subtree, which uses a different accent and squared corners.
    </section>
</body>
```

Custom properties inherit naturally — including across shadow boundaries — so this works for every component in the library.

## Cascade layers

The themes and the utilities put their rules into cascade layers, in this order:

| Layer          | What is in it          | File                   |
| -------------- | ---------------------- | ---------------------- |
| `el-tokens`    | The tokens of a theme. | `themes/*.css`         |
| `el-utilities` | Utility classes.       | `styles/utilities.css` |

A rule of your own that is in no layer wins over a layer, whatever its specificity and wherever it is loaded. So a token of the page overrides the theme also when its file comes first:

```css
:root {
    --el-color-accent: #e25b30;
}
```

If your own CSS is in layers too, as with Tailwind CSS v4, the order of the layers decides: the one that is named later wins. `styles/layers.css` holds the statement for the two layers of the library alone, to place them among yours.

Two things are in no layer, because a layer loses against every rule of the page that is in none, a reset included:

- `styles/native.css`. A reset in no layer (Tailwind CSS v3, a classic `reset.css`) would take the border and the padding of the controls away again. Its selectors carry the tag of the field, which is enough to win over a reset. Whether it moves into a layer, and reaches every native control of the page, is open in [#106](https://github.com/webtides/element-library/issues/106).
- The styles of the components.

`styles/utilities.css` is a third opt-in. It has one class so far: `el-visually-hidden` takes an element off the screen and keeps it for assistive technology.

## Beyond tokens

For overrides tokens can't express, the library exposes two other surfaces. The shipped `sketchy` theme uses the first one for the carousel, and brings a `@font-face` for its handwriting:

- **CSS Shadow Parts** — `::part(name)` reaches specific inner elements of shadow-DOM components. See each component's "CSS Parts" section for the names exposed by that element. Example: `::part(panel)` on `el-dropdown-element`.
- **Custom states** — host-level `:state(name)` selectors mirror component state. Example: `el-tab-link:state(active) { … }`, `:host(:state(open))` inside other components, `el-input-field:state(invalid) input`. See each component's docs for the states it exposes.

The form-field family (`form-field`, `input-field`, `textarea-field`, `select-field`, `checkbox-field`) renders in **light DOM**, so they're styled with normal descendant selectors instead of `::part()`. Their internal class hooks (`.field`, `.validity`, `.checked-indicator`, `.dropdown-indicator`, etc.) are documented per component.

## Available themes

| Theme             | Import                                               | Identity                                                                                                                                                                                      |
| ----------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Default**       | `@webtides/element-library/themes/default.css`       | Neutral, system-feeling. Modest radii, soft shadows, blue accent.                                                                                                                             |
| **High contrast** | `@webtides/element-library/themes/high-contrast.css` | WCAG-AAA-leaning. Near-black/white surfaces, 2px borders, 3px focus rings, no shadows, larger touch targets.                                                                                  |
